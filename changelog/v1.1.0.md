## Overview

v1.1.0 delivers the **complete scaffold CLI tooling layer** for the template. Every artifact type — pages, blocks, regular components, and UI components — now has a matching `create:*` and `delete:*` script with full `vite.config.ts` auto-wiring, test coverage, and documentation. The component directory layout was also restructured for long-term scalability.

**Key Highlights:**
- 10 new scaffold scripts covering the full component lifecycle
- 5 codebase analysis tools for auditing pages, components, blocks, and dependencies
- Component directories reorganised into `blocks/` and `ui/` for clarity
- Full vitest integration-test suite for every script
- `delete-page.js` bug fix and `vite.config.ts` corruption cleanup

## Added

### Component Lifecycle Scripts

- **`npm run create:component`** — scaffold a regular feature component with barrel export, types file, and optional unit test stub
- **`npm run delete:component`** — remove a component and its associated files; detects and warns about remaining import references
- Full interactive CLI prompts via shared `scripts/utils/cli.js`

**Documentation:**
- [Create Component](../docs/scripts/04-CREATE_COMPONENT.md)
- [Delete Component](../docs/scripts/05-DELETE_COMPONENT.md)

### Block Lifecycle Scripts

- **`npm run create:block`** — scaffold a layout block under `src/components/blocks/` with types file and barrel export
- **`npm run delete:block`** — remove a block and all associated files cleanly

**Documentation:**
- [Create Block](../docs/scripts/14-CREATE_BLOCK.md)
- [Delete Block](../docs/scripts/15-DELETE_BLOCK.md)

### UI Component Lifecycle Scripts

- **`npm run create:ui-component`** — scaffold a primitive UI component under `src/components/ui/`
- **`npm run delete:ui-component`** — remove a UI component and its associated files

**Documentation:**
- [Create UI Component](../docs/scripts/06-CREATE_UI_COMPONENT.md)
- [Delete UI Component](../docs/scripts/07-DELETE_UI_COMPONENT.md)

### shadcn/ui Registry Scripts

- **`npm run add:shadcn-component`** — install a component from the shadcn/ui registry and wire it into the project
- **`npm run manage:shadcn-registry`** — manage the local shadcn/ui component registry
- **`npm run list:registry-components`** — list all available registry components with metadata
- **`npm run fetch:registry-annotations`** — pull component annotations and metadata from the registry

**Documentation:**
- [Manage shadcn Registry](../docs/scripts/16-MANAGE_SHADCN_REGISTRY.md)
- [List Registry Components](../docs/scripts/17-LIST_REGISTRY_COMPONENTS.md)

### Codebase Analysis Scripts

- **`npm run analyze:pages`** — audit all pages, their entry points, and HTML templates
- **`npm run analyze:components`** — list all components with usage counts and dependency info
- **`npm run analyze:blocks`** — inspect all layout blocks
- **`npm run analyze:ui-components`** — inspect all UI primitives
- **`npm run analyze:deps`** — scan for unused dependencies and detect orphaned imports

**Documentation:**
- [Analyze Pages](../docs/scripts/08-ANALYZE_PAGES.md)
- [Analyze Components](../docs/scripts/09-ANALYZE_COMPONENTS.md)
- [Analyze Blocks](../docs/scripts/10-ANALYZE_BLOCKS.md)
- [Analyze UI Components](../docs/scripts/13-ANALYZE_UI_COMPONENTS.md)
- [Analyze Deps](../docs/scripts/11-ANALYZE_DEPS.md)

### Shared Script Utilities

Three new shared modules under `scripts/utils/`:

- **`component-deletion.js`** — common logic for locating and removing component files, unit tests, and resolving unused dependencies across all delete scripts
- **`component-generators.js`** — shared code-generation helpers (barrel exports, types stubs, component boilerplate) used by all create scripts
- **`component-utils.js`** — filesystem helpers, import-reference scanners, and path utilities shared across the script toolchain

## Changed

### Component Directory Structure

Components reorganised into purpose-specific subdirectories for scalability:

| Before | After |
|---|---|
| `src/components/layout/` | `src/components/blocks/layout/` |
| `src/components/footer/` | `src/components/ui/footer/` |
| `src/components/header/` | `src/components/ui/header/` |
| `src/components/section/` | `src/components/ui/section/` |
| `src/components/viewport-lazy-load/` | `src/components/ui/viewport-lazy-load/` |

All import paths updated across the codebase.

### Page Component Naming

Page-scoped components now carry the page name as a prefix to prevent naming collisions across pages:

| Before | After |
|---|---|
| `HeroSection.tsx` | `IndexHeroSection.tsx` |
| `FeaturesSection.tsx` | `IndexFeaturesSection.tsx` |
| `AboutSection.tsx` | `IndexAboutSection.tsx` |
| `HeavyChart.tsx` | `IndexHeavyChart.tsx` |

Components moved from `src/pages/index/components/sections/` directly into `src/pages/index/`.

### Script Refactors

- `scripts/create-component.js` — rewritten to delegate generation logic to shared `component-generators.js` (481 → ~180 lines of core logic)
- `scripts/delete-component.js` — rewritten to delegate to `component-deletion.js` (436 → ~150 lines of core logic)
- `scripts/utils/cli.js` — extended with additional prompt types and validation helpers

### Vite Config Cleanup

- Removed all ghost test-page entries from `rollupOptions.input` and `devServerMiddleware` left behind by the integration test suite
- Restored missing `htmlOutputPlugin` to the `plugins` array
- Fixed sentinel comment to exactly `// Add more page rewrites here as needed for new pages` so `create-page.js` regex injection works correctly

---

## Removed

- **`src/pages/dashboard/`** — example dashboard page removed; the template ships lean with only `index` and `page-not-found` pages
- **`src/components/ui/button/Button.tsx`** and **`Button.types.ts`** — removed in favour of adding Button via `npm run add:shadcn-component` from the registry
- **`tests/unit/components/ui/Button.test.tsx`** — removed alongside the Button component
- **`src/pages/NotFound.tsx`** — consolidated into `src/pages/page-not-found/PageNotFound.tsx`

---

## Fixed

- **`scripts/delete-page.js`** — template-literal bug where the warning message `Partially updated vite.config.ts (removed ${updateCount}/2 sections)` printed `${updateCount}` literally due to a single-quoted string wrapping a template expression. Fixed by switching to a template literal.
- **`vite.config.ts`** — over 100 ghost `rollupOptions.input` entries and `devServerMiddleware` route rewrites pointing to non-existent test pages were removed, preventing ESLint `ENOENT` crashes during linting.

## Developer Experience

### Updated Available Commands

```bash
# Page management
npm run create:page             # Scaffold a new MPA page
npm run delete:page             # Remove a page and all artifacts

# Component management
npm run create:component        # Scaffold a feature component
npm run delete:component        # Remove a feature component
npm run create:block            # Scaffold a layout block
npm run delete:block            # Remove a layout block
npm run create:ui-component     # Scaffold a UI primitive
npm run delete:ui-component     # Remove a UI primitive

# shadcn/ui registry
npm run add:shadcn-component    # Install a shadcn/ui component
npm run manage:shadcn-registry  # Manage local registry
npm run list:registry-components # List available components

# Analysis
npm run analyze:pages           # Audit pages
npm run analyze:components      # Audit components
npm run analyze:blocks          # Audit blocks
npm run analyze:ui-components   # Audit UI primitives
npm run analyze:deps            # Audit dependencies

# Testing
npm run test                    # Run unit tests (vitest)
npm run test:scripts            # Run script integration tests
npm run test:e2e                # Run Playwright e2e tests

# Code quality
npm run lint                    # ESLint
npm run type-check              # TypeScript validation
npm run build                   # Production build
```
